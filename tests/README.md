# tests/

The offline pytest suite: one `test_<module>.py` per module in `src/chatbot_eval/`, plus `test_docs_consistency.py`, which keeps the README, `config.example.toml` and the design docs in step with the code. Every test runs without network or API keys: models, the Gemini client and HTTP chatbots are replaced by fakes, and the whole suite takes a few seconds (`python -m pytest -q`). Passing tests therefore do not prove live Gemini behavior. To find the tests for a module, run `python tools/docmap.py uses src/chatbot_eval/<module>.py`.

## Rules here

- No network, API keys or corpus files: fake the model, the Gemini client and HTTP.
- Use short synthetic Hebrew fixtures; never corpus text.
- A test that needs a PDF builds one at test time (see `_pdf` in `test_pdf_markdown.py`); tests need
  neither LibreOffice, Tesseract nor Hebrew fonts.
- When a documentation rule can be checked mechanically, add it to `test_docs_consistency.py`; each
  guard names the file to update when it fails.
