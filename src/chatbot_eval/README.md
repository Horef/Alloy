# src/chatbot_eval/

The `chatbot_eval` package: all of Alloy's code, one module per component, assembled into workflows only by `cli.py`. Start with `cli.py` to see how a command runs. Components receive their collaborators (a `StructuredLLM`, a `ChatbotAdapter`, a cache) as arguments, which is why the test suite can run offline with fakes. `models.py` holds the shared Pydantic contracts and `validation.py` the input checks; `contracts.py` and `cache.py` define cache identities and keys. The design and rationale of each module are in `docs/design/` (index in `docs/ARCHITECTURE.md`); the tests for `x.py` are in `tests/test_x.py`.

## Rules here

- Every prompt treats document, question and answer text as untrusted data and asks for Hebrew output.
- Every model output passes deterministic validation (`validate_candidate`, quote provenance,
  `apply_fixed_claims`, `validate_prompt_package`) before it is accepted. Add a named rejection
  reason to the diagnostics rather than failing silently.
- New settings go in `config.Settings` (with validation), `config.example.toml` and the README
  parameter table; wire them through `GenerationOptions` and the CLI manifest parameters.
- Cache keys must change whenever outputs would change. Fingerprint prompts and schemas, and
  fingerprint deterministic code with `contracts.code_fingerprint` (ignores comments and
  docstrings), never raw file bytes, so unrelated edits do not force expensive re-extraction.
- Keep optional, cost-adding checks off by default and report their outcomes in
  `generation_diagnostics.json` or the run manifest.
- Heavy or optional dependencies are extras in `pyproject.toml`, imported inside the function that
  needs them, with an error that names the extra to install.
- Only `llm.py` imports the Gemini SDK and no module imports `cli.py` (`tools/docmap.py check`
  enforces both).
- Changing outcome classification, judge inputs or metric definitions changes what past runs mean.
  Say so in the commit body, and update the README and the `docs/design/` sections that define them.
- Validate behavior changes offline against real artifacts when useful (cached graphs in
  `{hova,keva}/.chatbot_eval_cache/graph/`, checkpoints in `*/outputs/*/generation_checkpoint.jsonl`),
  using throwaway scripts outside the repository.
